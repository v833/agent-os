# 常见问题与故障排查

本文档汇集在安装、配置、飞书长连接、CLI 运行与协作过程中最常见的问题排查指南。

---

## 一、飞书长连接与消息通信

### 1. 为什么在群里 @机器人 没有任何反应？

请按以下顺序逐项自查：

1. **检查控制台连接日志**：
   - 启动服务后，终端是否打印出 `[飞书] <botId> 长连接建立成功`？
   - 如果打印的是网络错误或握手失败，检查本地网络以及 `.env` 中的 App ID / Secret 是否正确。
2. **检查飞书后台事件订阅与长连接**：
   - 进入飞书开放平台 → 应用详情 → **「事件与回调」**。
   - 确认接收方式是 **「使用长连接接收事件」**（而不是配置了空回调 URL）。
   - 确认添加了 **`im.message.receive_v1`** 事件。
3. **检查应用是否已「创建版本并发布」**：
   - 飞书开放平台的所有事件订阅和权限，**必须在「版本管理与发布」中发布后才生效**。如果你只勾选了事件但没发版，长连接不会收到任何消息。
4. **确认机器人已被拉进群**：
   - 在飞书群设置的「群机器人」列表中，确认已添加该应用。
5. **确认是否为单话题第一条消息**：
   - 如果是在已经结束的旧话题中发送消息，检查该话题是否被 `/close` 关闭或会话已归档。建议新建一个飞书话题测试。

---

### 2. 启动时报错 `401 Unauthorized` 或凭据无效？

- 检查 `.env` 中的变量名与 `config/bots.json` 中 `appIdEnv` / `appSecretEnv` 是否完全一致。
- 确认 App Secret 没有包含多余的空格或前后换行。
- 如果在开放平台重置了 App Secret，旧 Secret 会立即失效，需同步更新 `.env`。

---

## 二、CLI 执行与环境问题

### 1. 报错 `spawn <cli> ENOENT`（找不到命令）？

- **原因**：Node.js 子进程无法在系统 `PATH` 环境变量中找到对应的 CLI 可执行文件。
- **排查方法**：
  1. 在系统终端直接运行 `codex --version`、`claude --version` 或 `agy --version`，确认命令本身可以执行。
  2. Windows 下部分工具安装在 npm 全局目录（如 `C:\Users\<User>\AppData\Roaming\npm`），请确认该路径已添加到系统的环境变量 `Path` 中。
  3. 修改了系统环境变量后，请**彻底重启终端或 VS Code**，让新 PATH 生效。

---

### 2. 任务一直卡在「执行中（蓝色卡片）」不结束？

- **原因通常有两个**：
  1. **模型请求境外 API 挂起/被墙**：CLI 正在等待 Anthropic / OpenAI / Google 的网络响应。请检查 `.env` 中是否正确配置了 `HTTPS_PROXY=http://127.0.0.1:10808`。
  2. **任务陷入复杂死循环**：例如模型在反复修改同一个文件或跑一个卡死的命令。
- **解决方法**：
  - 点击卡片右下角的 **「停止」** 按钮强制终止。
  - 在 `.env` 中设置单轮执行超时上限（如 `CLI_TIMEOUT_MS=300000`，即 5 分钟超时自动收口）。

---

### 3. 报错 `Authentication required`（未认证/需要登录）？

- **Antigravity (agy)**：在群中直接发送 `@机器人 /agy login`，通过飞书卡片完成 OAuth 授权码粘贴。
- **DimAgent**：在群中发送 `@机器人 /dimagent login`，按卡片提示在浏览器输入设备码完成认证。
- **Codex / Claude Code**：在开发机本地终端先跑一次 `codex exec` 或 `claude` 完成首次登录认证，后续无头运行即可复用已保存的 Token。

## 三、团队协作与鉴权

### 1. 为什么点击卡片上的「停止」按钮提示无权限？

- **鉴权机制**：ThreadPilot 严格限制**只有当前任务的发起人**才能点击「停止」按钮终止任务。
- 这项设计是为了防止在多人协作的大群中，旁观成员误触按钮意外打断正在执行的关键研发任务。

---

### 2. 为什么其他成员调用 `dispatch_task` 提示被拒绝？

- **权限限制**：全团队中**只有 Team Leader（CEO 助理）**拥有派发任务的特权。
- 普通开发成员或 QA 成员只能执行指派给自己的任务，执行完毕后结果固定回传给 Team Leader，禁止成员之间随意互派导致调用风暴。

---

### 3. 多台 Bot 在同一个群里，会不会消息互相抢占？

- **不会**。ThreadPilot 的事件路由严格基于飞书消息中的 `@mention` 实体解析。
- 群里 `@开发工程师`，只有开发 Bot 会唤醒其绑定的 CLI；其他 Bot 会自动忽略该消息，各走各的话题会话，互不干扰。

---

## 四、网络代理与跨国访问

### 1. 本机开启了梯子，但 ThreadPilot 里的 CLI 仍然提示网络超时？

- 子进程不会自动抓取 Windows 系统的 Clash / v2ray 虚拟网卡设置，必须显式在 `.env` 中配置环境变量：
  ```dotenv
  HTTP_PROXY=http://127.0.0.1:10808
  HTTPS_PROXY=http://127.0.0.1:10808
  ALL_PROXY=http://127.0.0.1:10808
  NO_PROXY=localhost,127.0.0.1,::1
  ```
- 确认你的代理客户端本地监听端口（常见的有 7890、10808、10809），将端口改为你本机客户端的实际端口。
