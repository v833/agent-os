# 与竞品（BotMux）的能力对比与改进方向

本文档对比 Agent OS 与同类开源工具 BotMux 的架构设计与功能特性，分析两者的侧重点，并列出 Agent OS 目前存在的不足与后续补全方向。

---

## 核心设计理念对比

- **定位重心**：BotMux 偏向终端直连与会话桥接平台；Agent OS 聚焦于角色化多智能体研发协同。
- **进程机制**：BotMux 基于 tmux 与 PTY 管理真终端进程；Agent OS 基于 Headless 子进程与标准 ACP 协议。
- **交互界面**：BotMux 提供飞书流式卡片与网页端交互式终端；Agent OS 提供飞书结构化卡片、澄清问卷与方案确认。
- **团队协作**：BotMux 采用同群多 Bot 平级路由，适合互相 Review；Agent OS 采用明确的四角色流水线（助理、产品、开发、QA）。
- **质量门禁**：BotMux 依赖 CLI 自身验证，无平台级隔离；Agent OS 拥有独立的工作区快照、固定 revision 与三态门禁。
- **业务系统集成**：BotMux 支持本地 SQLite 与 Webhook；Agent OS 支持飞书多维表格双向看板与飞书云文档原生交付。

---

## Agent OS 的现有不足与待补齐能力

通过与 BotMux 现有功能矩阵的比对，Agent OS 在以下方面存在不足，建议作为后续演进方向：

### 1. 终端直连与 PTY 会话接管
- **竞品现状**：BotMux 支持可交互的 Web 终端，移动端提供悬浮快捷键（Esc、Ctrl+C、方向键），支持 `/adopt` 接管本地已有的 tmux 会话，支持 `/relay` 将本地会话整体搬入群聊。
- **当前不足**：Agent OS 采用纯 Headless 运行模式。当底层 CLI 输出需要原生交互时，用户在飞书界面无法直接发送按键，也无法将本地正在运行的 CLI 会话接入飞书。
- **演进方向**：引入轻量级 PTY/Web 终端连接插件，在任务遇到非结构化输入阻塞时，允许发起人临时通过浏览器直连控制台。

### 2. CLI 适配器矩阵覆盖
- **竞品现状**：BotMux 内置了 20 余款 CLI 适配器（覆盖 Claude Code、Codex、Cursor、Gemini、OpenCode、Kimi、TRAE/CoCo、Grok 等），支持在群内通过 `/cli <name>` 动态指定执行引擎。
- **当前不足**：Agent OS 目前深度适配了 Claude、Codex、DimAgent 和 Antigravity (agy)，其余引擎依托标准 ACP (Agent Client Protocol) 接入，对未原生提供 ACP 接口的 CLI 覆盖度不足。
- **演进方向**：在 `src/plugins/engines/` 中扩展更多适配器，提供开箱即用的配置项。

### 3. 外部事件与 Webhook 触发
- **竞品现状**：支持开放的 Webhook 入口与 API 触发，能接收来自 GitHub Actions、Sentry、Prometheus 等外部系统的告警通知并自动开工。提供 Oncall 模式，拉入报警群后自动识别并介入。
- **当前不足**：Agent OS 的任务触发目前主要依赖飞书群消息、`/schedule` 定时器以及飞书多维表格（Bitable）反向轮询拉起，缺乏通用的 HTTP Webhook 接收端点。
- **演进方向**：增加 Webhook 触发插件，允许外部系统通过标准的 HTTP POST 请求携带项目目录与 Prompt 直接创建执行会话。

### 4. 交付质量反馈收集闭环
- **竞品现状**：BotMux 在最终回答卡片上常驻三态反馈按钮（“结论可用 / 有效推进 / 结论有误”），点击后可提交原因并沉淀至本地 SQLite 数据库。
- **当前不足**：Agent OS 在执行结束时仅展示状态（成功/失败）与链路 Metrics（耗时、Token），缺乏真人对交付质量的结构化打分与反馈回路。
- **演进方向**：在任务结果卡片上增加轻量反馈按钮，将评价结果同步回写至任务看板或本地日志。

### 5. 语音总结与多模态输出
- **竞品现状**：BotMux 配套了语音总结（TTS），卡片底部提供语音播放按钮，适合移动端通勤时收听进度。
- **当前不足**：Agent OS 目前仅支持输入端的多模态解析（识别群聊图片），未配置输出端的语音朗读能力。
- **演进方向**：增加可选的飞书语音消息生成能力。

## Agent OS 的差异化优势

在看到差距的同时，Agent OS 在工程研发流程和协同深度上具备以下差异化能力：

1. **确定性的角色分工与职责边界**：内置四角色契约，产品经理必须通过结构化表单澄清并输出可验收方案，真人确认后才进入开发，QA 在独立快照中运行测试，杜绝了多 Bot 之间无序闲聊或破坏代码库。
2. **飞书多维表格与云文档原生集成**：一键初始化任务看板并支持反向拉起；产品方案直接交付为飞书云文档（Docx XML 原生排版），而非仅停留在聊天消息中。
3. **基于 Cordis 的插件化内核**：所有引擎、命令、协作策略均为独立插件，通过声明式配置文件即插即用，具备更优的工程解耦性。
