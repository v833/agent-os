# 任务看板

Agent OS 可以把任务生命周期实时同步到飞书多维表格（Bitable），并反过来从表格中「待处理」记录自动拉起新任务，形成双向闭环。看板支持一键初始化、链接查询与状态大盘。

---

## 一键初始化看板

在群聊中发送：

```text
@机器人 /board init [看板名称]
```

例如：

```text
@CEO助理 /board init 研发任务看板
```

系统会自动完成以下动作：

1. 创建一张多维表格（App）；
2. 写入 10 个标准业务字段与 6 色状态枚举（任务状态流转）；
3. 配置看板视图；
4. 挂载双向同步服务，并把配置持久化到本地，重启后自愈。

初始化过程中会展示进度卡片，完成后返回就绪卡片，内含看板访问链接与数据表 ID。

### 覆盖重建

如果已经挂载了看板，再次执行 `/board init` 会先弹出冲突确认卡片，避免误覆盖。确认后执行：

```text
@机器人 /board init --force [看板名称]
```

---

## 查看看板链接

```text
@机器人 /board link
```

返回当前已挂载看板的名称、直达链接、数据表 ID 与更新时间。

---

## 查看同步状态

```text
@机器人 /board status
```

返回看板运行状态大盘，包括：

- 挂载状态与服务状态（正常 / 降级 / 初始化中）；
- 已关联任务数、已见表格记录数、待冲刷快照数；
- 事件单向同步（Agent OS → 表格）与待处理反向拉起（表格 → Agent OS）是否开启。

---

## 双向同步与反向拉起

### Agent OS → 表格

任务生命周期事件（开始、成功、失败、暂停、取消、QA 结论）会实时同步到表格对应记录，字段状态自动流转。

### 表格 → Agent OS

在表格中新增一条「待处理」记录（并填写任务描述，必要时指定群聊 ID），看板服务轮询到后会反向拉起一个新任务开工：

- `/board init` 方式初始化的看板会自动绑定初始化群聊作为回退群聊，记录未填「群聊 ID」时也能在该群开工；
- 静态配置方式的看板需手动指定 `fallbackChatId`，否则缺少群聊 ID 的记录会被跳过。

### 重启自愈

看板配置持久化到本地（`data/bitable-board.json`），Agent OS 重启后会自动重新挂载看板并恢复同步与轮询，无需重复初始化。
