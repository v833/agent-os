# 基础使用说明书

本文档介绍如何在飞书话题群中与 Bot 进行日常交互、查看执行状态、参与表单澄清与控制工作目录。

---

## 一、话题即会话：发起任务与多轮追问

ThreadPilot 的核心设计是 **“一个飞书话题（Thread）对应一个独立的 CLI 编程会话”**。

### 1.1 发起全新任务
在飞书群中，点击底部的输入框，**先键入你的需求并 `@目标机器人`**：
```text
@开发工程师 请分析当前仓库中所有的 TODO 项，并按紧急程度列出清单
```
发送后，系统会为此话题拉起一个独立的无头 CLI 进程，开始执行。

### 1.2 在同一话题中持续追问
当任务完成后，如果需要继续修改或深入提问，**直接在该话题下方点击「回复」**：
```text
请优先帮我修复第二项关于并发锁的 TODO
```
- **上下文自动继承**：Bot 会自动调出上一轮会话的历史记忆，知道“第二项”指代什么，无需重复贴代码或描述背景。
- **不同话题完全隔离**：你在群里开辟的另一个话题不会受到该任务上下文的影响，每个话题独享独立的进程与会话状态。

### 1.3 私聊、独立任务与团队模式
- **群聊 `@Team Leader`（team 模式）**：由 Leader 统一派发产品、开发和 QA，成员结果固定回到 Leader。
- **群聊 `@普通成员`（standalone 模式）**：保留该成员自身角色与 Skill，独立完成当前任务，不与其他 Bot 协作或自动回传。
- **私聊（direct 模式）**：Bot 忽略团队角色、团队 Skill 和产品流程，直接执行；若需要生成飞书云文档，可输入 `/doc <需求>` 显式开启。

## 二、实时执行卡片与任务状态机

任务执行期间，飞书话题中会渲染一张**一秒节流刷新的高保真交互卡片**。

### 2.1 卡片四色状态流转

| 状态 | 卡片颜色 | 含义与展示细节 |
| :--- | :---: | :--- |
| **执行中** | 🔵 蓝色 | 实时展示当前正在调用的工具（如查看文件、运行 `pnpm test`、修改文件）、已运行秒数与累计 Token 消耗。 |
| **已完成** | 🟢 绿色 | 任务成功完成，展示结论摘要。如回答较长，会自动以话题消息形式跟帖补充。 |
| **执行失败** | 🔴 红色 | 发生异常、语法错误或超时，展开后可查看具体报错原因与排查提示。 |
| **已中止** | ⚪ 灰色 | 任务被人工点击「停止」按钮强制终止，底层进程树已被安全回收。 |

### 2.2 任务安全停止（发起人防误触）
执行卡片右下角始终常驻一个 **「停止」** 按钮：
- 当模型陷入死循环、生成方向偏差或耗时过长时，随时点击即可秒级打断。
- **内置严格鉴权**：系统会比对飞书 OpenID，**只有当前任务的发起人点击才有效**，避免公共群中其他成员误触打断你的工作。

## 三、消息格式与多模态资源处理

ThreadPilot 原生支持富文本、代码块与多模态图片识别：

1. **直接粘贴代码**：支持在消息中直接粘贴 Markdown 代码块，Bot 会原样送入 CLI 提示词。
2. **带图提问（重要技巧）**：
   - **务必将图片与文字描述放在同一条消息中发送**（例如：贴一张网页报错截图，并在同一条消息中输入 `@开发工程师 页面出现了这个红屏报错，请定位源码`）。
   - ThreadPilot 会自动通过飞书 OpenAPI 下载原图并在多模态模型中解析，如果只发一张纯图片而不带任何文字说明，系统将无法提取有效指令。
3. **日志与附件文件**：直接在话题中上传 `.log`、`.json` 或 `.txt` 文件，CLI 会自动下载到工作区并进行分析。

## 四、需求澄清问卷流（表单交互）

当你的原始需求存在歧义或技术选型分歧时，Bot（特别是产品经理或启用了 `grill-me` 技能的成员）不会凭空猜测，而是会调用结构化澄清工具弹出**飞书问卷表单卡片**：

```text
┌──────────────────────────────────────────────────┐
│ ❓ 需求澄清：请确认以下技术选型                   │
│                                                  │
│ 1. 鉴权方式希望采用哪种方案？                     │
│    🔘 JWT Token (推荐)                           │
│    ⚪ Session Cookie                             │
│                                                  │
│ 2. 数据库变更策略：                              │
│    ☑️ 自动运行 Prisma 迁移脚本                    │
│    ⬜ 仅输出 SQL 变更脚本，由人工执行             │
│                                                  │
│ [ 补充说明输入框...                            ] │
│ [ 提交确认 ]                                     │
└──────────────────────────────────────────────────┘
```

- 你直接在手机或电脑卡片上点选勾选框，并点击「提交确认」。
- 提交后，ThreadPilot 会将结构化选项实时送回正在运行的 CLI，继续后续研发，避免无效反复拉扯。

## 五、工作区与工程目录切换 (`/cd`)

默认情况下，每台 Bot 运行在 `config/bots.json` 中配置的 `workspace` 目录下。如果你需要在飞书里临时切换到本机的其他项目：

- **查看当前话题的工作目录**：
  ```text
  @开发工程师 /cd
  ```
- **切换到指定项目目录**（支持相对路径与绝对路径）：
  ```text
  # Windows 绝对路径
  @开发工程师 /cd D:\workspace\frontend-project

  # 相对路径
  @开发工程师 /cd ../another-service
  ```
- 切换成功后，当前话题的 CLI 会话将重置，以新目录作为后续读写文件和执行命令的根基。

## 六、常用话题控制命令

在话题中，除了自由对话，你还可以输入斜杠命令快速操作：
- `@机器人 /status`：查看当前会话的底层 CLI 引擎、运行时长与资源消耗。
- `@机器人 /new`：立即清空当前话题的历史对话记忆，开启全新的一轮对话。
- `@机器人 /compact`：通知底层 CLI 压缩历史上下文，释放上下文 Token 窗口。
- `@机器人 /help`：在飞书群中直接打印所有可用命令清单。
