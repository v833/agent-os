# 飞书应用创建与配置指南

ThreadPilot 通过飞书开放平台官方的 **WebSocket 长连接** 与你的飞书工作台通信。服务运行在本地或内网，**无需公网 IP，也无需配置反向代理或暴露任何外部端口**。

本文档手把手带你完成飞书自建应用的创建、长连接开启、权限申请与版本发布。

---

## 一、创建飞书企业自建应用

1. 登录 [飞书开放平台开发者后台](https://open.feishu.cn/app)。
2. 点击右上角的 **「创建自建应用」**（或「智能体应用」）。
3. 填写基本信息：
   - **应用名称**：例如 `代码开发助手`（如果你配置多 Bot，可按角色命名，如 `产品经理`、`QA 测试` 等）。
   - **应用副标题**：例如 `在飞书话题里执行代码开发与审查`。
   - **应用图标**：上传一个辨识度高的头像，便于群聊中区分。
4. 点击「创建」进入应用详情页。

---

## 二、开启机器人能力

1. 在左侧导航栏点击 **「添加应用能力」**。
2. 找到 **「机器人」** 卡片，点击「添加」并确认。
3. 添加成功后，左侧导航栏会出现「机器人」相关设置项。

---

## 三、配置长连接接收事件（关键步骤）

1. 在左侧导航栏点击 **「事件与回调」**。
2. 在页面顶部的 **「事件接收方式」** 中，选择 **「使用长连接接收事件」**。
   > **为什么选长连接？**  
   > 传统 Webhook 回调需要你有公网 IP 和备案域名，且必须开放端口；而长连接由本地 ThreadPilot 进程主动向飞书发起安全 WebSocket 双向连接，内网穿透零成本，断线自动重连。
3. 点击页面中的 **「添加事件」**，搜索并勾选以下核心事件：
   - `im.message.receive_v1`（接收消息 v2.0）—— **必选**，用于接收群聊/私聊中 @机器人的文本、代码、图片与附件。
   - `drive.notice.comment_add_v1`（添加云文档评论）—— **可选**（仅产品经理 Bot 需要），用于在飞书云文档产品评审时，直接在评论中 @机器人 自动触发文档修改。
4. 点击「保存」。

---

## 四、申请必要权限清单

在左侧导航栏点击 **「权限管理」**。为了使 ThreadPilot 正常接收消息、下载附件、发送流式交互卡片和操作云文档，需要开通以下权限范围：

| 权限名称 | 权限代码 (Scope) | 必需程度 | 用途说明 |
| :--- | :--- | :---: | :--- |
| 获取与发送单聊/群聊消息 | `im:message` | **必须** | 核心消息收发 |
| 以应用的身份发消息 | `im:message:send_as_bot` | **必须** | 机器人发卡片与话题回复 |
| 获取用户基本信息 | `contact:user.base:readonly` | **建议** | 识别发起人姓名与身份 |
| 获取用户 user ID | `contact:user.id:readonly` | **建议** | 发起人鉴权（停止按钮防误触） |
| 读取与下载消息中的资源文件 | `im:resource` | **建议** | 解析用户在话题中发送的图片与文档 |
| 查看与创建多维表格数据 | `bitable:app` | 可选 | 使用 `/board` 任务看板双向同步功能时需要 |
| 查看、编辑云文档 | `docx:document` | 可选 | 产品经理 Bot 自动创建/修改飞书云文档时需要 |

> 提示：在权限管理页面顶部的搜索框中直接粘贴权限代码（如 `im:message`），即可快速定位并批量勾选。

---

## 五、发布应用版本

飞书应用的所有权限和能力，**必须发布新版本后才能正式生效**：

1. 在左侧导航栏点击 **「版本管理与发布」**。
2. 点击右上角 **「创建版本」**。
3. 填写版本号（如 `1.0.0`）与更新说明（如 `初始化应用`）。
4. 在可用范围选择中，选择「所有员工」或指定你的开发团队所在的部门/成员。
5. 点击 **「保存」** 并点击 **「申请发布」**。
   - 如果你是企业管理员，页面通常会直接通过发布并立即生效。
   - 如果不是管理员，需要等待企业管理员在飞书中审批通过。

---

## 六、获取凭证并写入本地配置

1. 在左侧导航栏点击 **「凭证与基础信息」**。
2. 复制以下两项凭据：
   - **App ID**（形如 `cli_a1b2c3d4e5f6xxxx`）
   - **App Secret**（形如 `xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`）
3. 打开本地项目的 `.env` 文件，将凭据写入对应变量：
   ```dotenv
   FEISHU_DEVELOPER_APP_ID=cli_a1b2c3d4e5f6xxxx
   FEISHU_DEVELOPER_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```

---

## 七、将机器人加入群聊

1. 打开飞书客户端，进入你要进行代码协作的话题群。
2. 点击群右上角的「...」设置 → **「群机器人」** → **「添加机器人」**。
3. 在企业自建应用列表中，搜索找到你刚刚发布的机器人并添加进群。
4. 现在你可以在群话题中 `@机器人` 发送任务了！

---

## 八、多 Bot 团队模式应用配置建议

如果你计划组建包含多个不同角色（如产品经理、开发工程师、QA 测试）的团队：
- **推荐为每个角色在开放平台创建独立的自建应用**（例如分别命名为 `[Bot] 开发工程师`、`[Bot] 产品经理`、`[Bot] QA 工程师`）。
- 每个应用拥有独立的 App ID / App Secret，在 `.env` 中分别配置：
  ```dotenv
  FEISHU_DEVELOPER_APP_ID=cli_xxx
  FEISHU_DEVELOPER_APP_SECRET=xxx

  FEISHU_PRODUCT_APP_ID=cli_yyy
  FEISHU_PRODUCT_APP_SECRET=yyy

  FEISHU_QA_APP_ID=cli_zzz
  FEISHU_QA_APP_SECRET=zzz
  ```
- 把多个机器人拉进同一个群聊：直接 `@普通成员` 时由该成员独立承接；`@Team Leader` 时开启团队模式，由 Leader 统一派发并汇总。
