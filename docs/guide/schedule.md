# 定时任务

Agent OS 支持在飞书群聊中直接创建、查看与删除定时任务。到点后，系统会主动在配置的话题中开工执行，并把结果作为卡片回复发回该话题。

---

## 创建定时任务

```text
@机器人 /schedule add "<周期>" <任务描述>
```

例如，每 30 分钟检查一次服务健康：

```text
@开发工程师 /schedule add "每 30 分钟" 检查当前项目的服务健康状态并汇报结果
```

创建成功后，机器人会回复任务编号（形如 `#sched-001`）与下次触发时间。

### 周期语义

周期既可以是标准 5 段 cron 表达式，也可以是简化自然语言：

| 写法 | 含义 |
| :--- | :--- |
| `每 30 分钟` | 每 30 分钟执行一次（N 范围 1-59） |
| `每小时` | 每小时整点执行一次 |
| `每 3 小时` | 每 3 小时执行一次（N 范围 1-24） |
| `每天` | 每天 00:00 执行一次 |
| `每天 9:00` | 每天上午 9 点执行一次 |
| `0 9 * * *` | 标准 5 段 cron，每天 9 点执行 |

> 定时任务周期解析遵循本机时区；创建后持久化到本地数据文件，服务重启后自动恢复。

---

## 查看定时任务

```text
@机器人 /schedule list
```

返回当前 Bot 名下的全部定时任务，包含编号、周期描述、任务摘要与下次触发时间。

---

## 删除定时任务

```text
@机器人 /schedule remove <任务编号>
```

例如：

```text
@开发工程师 /schedule remove sched-001
```

也支持带 `#` 前缀的写法：`/schedule remove #sched-001`。

---

## 触发后的开工行为

- 到点时，系统先向配置的话题发送一条锚点消息（`⏰ 定时任务：…`），随后任务卡片与最终结果作为该消息的回复出现在话题中。
- 任务复用的是创建时刻的话题会话上下文：若话题当时忙碌（已有任务在执行）或已关闭，本轮会跳过并记录，避免并发冲突或往已归档话题写入。
- 执行引擎、工作目录与权限均沿用创建任务时所在话题的配置，因此创建时请确认当前话题绑定的是期望的引擎与目录。

> 提示：定时任务由发起人在对应话题创建，删除操作同样在话题内用 `/schedule remove` 完成。
