# 团队 Bot 角色与协作流程

Agent OS 的核心优势不仅在于单机 CLI 的执行，更在于它组建了一支各司其职的**虚拟数字化产研团队**。

---

## 团队成员档案

### 1. CEO 助理 (`ceo-assistant` - Team Leader)
- **职责**：宏观战略理解、跨部门目标拆解、团队任务组织派发与最终成果汇总。
- **擅长**：统筹全局，把模糊的业务诉求转化为清晰的执行路线图，并负责组织其他成员推进。
- **何时找它**：当你有综合性需求、跨阶段项目（例如“搭建一个新系统”、“全面重构某模块并补充文档”）时，直接找 CEO 助理。

### 2. 产品经理 (`product`)
- **职责**：需求深度挖掘、业务边界澄清，并形成可落地的规格说明（Spec）与切片任务清单（Tickets）。
- **技能配备**：自带需求访谈（grill-me）、规范转化（to-spec）、飞书云文档直接创建（lark-doc）等专业能力。
- **何时找它**：需求不够具体、需要产品原型或方案评审时。

### 产品方案交付形态

产品经理产出的方案有两种交付形态，**同一份方案二者互斥，不要双维护**：

1. **飞书云文档**（`lark-doc` 模式）：方案写为飞书在线文档，文档内同时包含「产品说明」与「实现任务（Tickets）」章节，提交时给出文档链接。
2. **本地 Markdown**（`local` 模式）：方案以 Spec 与 Tickets 两个本地文件形式真实落盘到工作区。

无论哪种形态，方案生成后都会在群里弹出**发起人确认卡**。只有任务发起人可以点击确认。确认后有两种走向：**直接确认**只记录「产品方案已就绪」；选择**「确认并交给 Leader」**会把方案作为团队任务派发给 CEO 助理，由其用 `dispatch_task` 派给合适的开发成员继续研发。提交前必须完成需求澄清。

### 产品评审评论回路

当方案以飞书云文档交付后，你可以在文档中**直接 @产品经理 发表评论**，Agent OS 会自动：

1. 按文档 token 找回对应的待确认产品会话；
2. 恢复该产品经理的原 CLI 会话，让其根据评论精确修改文档；
3. 把一段简短的修改说明回复到同一条评论上。

评论处理在同一会话内串行排队，避免多评论并发改写；评论是否「解决」由你复查后决定，系统不会替你关闭评论。

### 3. 开发工程师 (`developer`)
- **职责**：工程实现、功能编码、依赖维护、本地测试与代码重构。
- **特性**：行动迅速，专注在代码层面高质高效地完成由产品经理或 CEO 助理明确的具体技术任务。
- **何时找它**：有确切的 Bug 修复、技术需求、接口开发或工程搭建时。

### 4. 测试与质量保障工程师 (`qa`)
- **职责**：质量兜底、回归测试、自动化用例补充与缺陷反馈。
- **核心机制（QA Gate）**：QA 不会在开发工程师正在编辑的目录下直接运行测试，而是自动克隆一份**隔离工作区快照**，在纯净环境下执行构建与测试脚本，给出严谨的质量判定。
- **何时找它**：代码交付前把关、编写自动化测试套件、复现复杂的回归缺陷。

### QA 质量闸门三态闭环

开发完成后，系统会把交付版本物化为 QA 专用隔离快照，并固定该快照的工作树 revision。QA 审查后输出一个与 revision 绑定的结构化结论，三态路由如下：

| 结论 | 语义 | 系统动作 |
| :--- | :--- | :--- |
| `pass` | 审查通过 | 结束交付链路，通知开发与团队 |
| `changes_requested` | 需要返工 | 退回开发工程师修复缺陷，随后重新生成快照复审 |
| `blocked` | 阻塞 | 升级给 Team Leader 处理环境 / 权限 / 协议问题 |

QA 会校验报告 revision 与快照实际 revision 是否一致，不一致即判定阻塞，防止「审查了与交付不一致的版本」这类失真结论。

## 经典协同场景演示

```
[用户在飞书发起任务] 
       │
       ▼
[CEO 助理] ── 拆解目标并组织分工
       │
       ├─► [产品经理] ── 澄清细节，生成产品说明书与交付切片
       │         │
       │         ▼
       │     (用户点击飞书卡片确认方案)
       │         │
       ├─► [开发工程师] ── 基于确认方案编写代码与本地实现
       │         │
       │         ▼
       └─► [QA 工程师] ── 自动创建隔离快照，执行验收与门禁测试
                 │
                 ▼
          (通过后由 CEO 助理汇总结果汇报给用户)
```

通过这一闭环，整个开发生命周期完全在飞书群中自主推进，既保障了效率，又保证了质量。
