# CLI 登录

部分编程 CLI（如 Antigravity、DimAgent）在首次使用时需要登录认证。ThreadPilot 通过飞书卡片引导你完成登录，无需离开飞书界面。任务因认证失败时，系统也会自动补发登录卡片。

---

## 主动发起登录

为当前会话绑定的引擎发起登录：

```text
@机器人 /login
```

为指定引擎发起登录：

```text
@机器人 /agy login
```

发送后，机器人弹出登录卡片，后续按卡片提示完成授权。

> 提示：`/<引擎> login` 会为指定引擎发起登录，`/login` 则针对当前会话已绑定的引擎。

---

## 自动触发登录

当任务因引擎未认证而失败时（例如 Antigravity 提示 `Authentication required`，或 DimAgent 提示需要 `auth login`），ThreadPilot 会自动在失败话题中补发登录卡片，引导你完成登录后重试任务。同一会话已有待完成登录卡片时不会重复发卡。

---

## 两种登录链路

### Key 模式（OAuth 授权码粘贴）

适用于 Antigravity（agy）等引擎：

1. 登录进程启动后，卡片展示授权链接；
2. 你在浏览器中打开链接并完成授权，复制授权码；
3. 在飞书卡片中粘贴授权码并确认，ThreadPilot 将授权码注入登录进程完成登录。

授权码与本次启动的 PKCE 绑定，需使用当前进程打印的授权 URL 完成授权。

### Device 模式（设备码等待）

适用于 DimAgent 等引擎：

1. 登录进程启动后，卡片展示完成 URL 与设备码；
2. 你在浏览器中打开链接并输入设备码完成授权；
3. 授权成功后登录进程自动完成，卡片流转为成功状态。

---

## 登录安全边界

- 只有任务发起人可以提交登录 key；其他成员点击会被拒绝。
- 登录流程仅保存在内存中，ThreadPilot 重启后旧卡片自然失效。
- 登录完成后的令牌由底层 CLI 自身保存（如 agy 写入 `~/.gemini/antigravity-cli`），后续 headless 运行免登录。

> 提示：部分引擎（如 Codex / Claude）不提供卡片登录协议，执行 `/login` 时会提示「暂不支持卡片登录」，这类引擎的认证通常在宿主环境预先配置。
