# 产品介绍与架构

## ThreadPilot 是什么

**ThreadPilot 是一座连接飞书与本地 AI 编程 CLI 的桥梁。**

它作为一个常驻后台服务（Daemon），通过 WebSocket 长连接监听飞书消息。当你在飞书话题群中 `@机器人` 时，ThreadPilot 会在后台为你启动一个独立的无头 AI 编程 CLI 进程（支持 OpenAI Codex、Anthropic Claude Code、DimAgent、Google Antigravity 与标准 ACP 服务），并将终端执行轨迹、工具调用细节和用量统计实时渲染为飞书流式交互卡片。

任务成功后结论直接回到卡片正文，任务执行中发起人可一键点击终止；同一话题自动保留会话上下文，跨进程重启后仍可续接恢复。

---

## 它解决什么核心痛点？

1. **CLI 跑在开发机，人却在手机/会议室**  
   直接用终端跑 Claude Code 或 Codex，你必须一直守在电脑前盯着黑屏滚动。ThreadPilot 把执行状态实时推送到飞书卡片中，你在手机、平板或会议室里即可随时查看动作、追问、打断或验收结果。

2. **多话题多任务，上下文不再串扰**  
   飞书的“话题（Thread）”天然对应一个独立的任务边界。ThreadPilot 将每个飞书话题映射为一个独立的 CLI 会话。你在 A 话题修 Bug、B 话题查性能，两个任务的执行进程与上下文完全隔离，绝不互相串扰。

3. **单模型容易盲目，需要多角色相互制约**  
   单个 AI 容易过度设计或写出带缺陷的代码。ThreadPilot 支持在同一个飞书群中部署多台不同角色的 Bot（如开发工程师由 Claude 驱动、代码审查与 QA 由 Codex 驱动），由 Team Leader 统一派发任务、接收成员结果并向用户收口。

4. **内网部署零门槛，不需要公网 IP**  
   很多开发者机房或个人电脑处于公司内网或家庭 NAT 之后。ThreadPilot 采用飞书官方 WebSocket 长连接模式，服务主动向飞书发起长连，**不需要公网 IP、不需要配置反向代理或暴露 Webhook 端口**。

## 系统工作原理

```text
┌─────────────────────────────────────────────────────────┐
│                       飞书客户端                         │
│  (手机 / 电脑话题群: 发起任务、查看卡片、点击停止、表单澄清)    │
└────────────────────────────┬────────────────────────────┘
                             │  WebSocket 长连接 (无需公网IP)
                             ▼
┌─────────────────────────────────────────────────────────┐
│                  ThreadPilot 运行时                      │
│                                                         │
│   ┌───────────────┐     ┌───────────────┐               │
│   │ 飞书连接服务   │ ──► │  Router 路由  │               │
│   │ (ctx.lark)    │     └───────┬───────┘               │
│   └───────────────┘             │                       │
│                                 ▼                       │
│                         ┌───────────────┐               │
│                         │  任务编排服务 │               │
│                         │ (ctx.tasks)   │               │
│                         └───────┬───────┘               │
│                                 │                       │
│         ┌───────────────────────┴───────────────────────┐
│         ▼                                               ▼
│  ┌──────────────┐                               ┌──────────────┐
│  │ 卡片节流刷新 │                               │  无头 CLI 进程│
│  │ (ctx.cards)  │ ◄─────── 流式事件解析 ────────│  (Runner/ACP)│
│  └──────────────┘                               └──────────────┘
│                                                         │
└─────────────────────────────────────────────────────────┼───────┘
                                                          ▼
                                            ┌───────────────────────────┐
                                            │ 本地代码库 / Bot 工作区     │
                                            │ (Codex / Claude / DimAgent│
                                            │  / Antigravity agy)       │
                                            └───────────────────────────┘
```

1. **消息监听与路由**：ThreadPilot 启动后连接飞书开放平台长连接，收到群消息后解析 `@` 的目标 Bot、话题 ID 与文本指令。
2. **会话管理**：根据「群 ID + 话题 ID + Bot ID」定位会话。如果是该话题第一条消息，初始化全新 CLI 会话；如果是追问，携带上一轮的 CLI 会话 ID 执行 `resume` 续接。
3. **安全无头子进程**：根据 `config/bots.json` 配置的引擎与接入模式（`headless` 或 `acp`），通过子进程安全启动对应 CLI，注入 Bot 专属的工作目录、环境变量与网络代理。
4. **实时事件与卡片节流更新**：监听 CLI 的 stdout/stderr 流式事件，提取工具调用（如读文件、执行 bash、运行测试）、Token 消耗与耗时。通过 1 秒节流更新器刷新飞书卡片，避免高频请求触发飞书开放平台 API 频控。
5. **权限与任务停止**：任务发起人可在卡片上随时点击「停止」按钮，ThreadPilot 会通过跨平台进程树清理强制终止子进程，确保不会残留孤儿进程占用系统资源。

## 核心架构原则：一切皆为插件

ThreadPilot 基于 [Cordis](https://cordis.chat/) 微内核插件架构设计，能力完全解耦：
- **能力由插件组装**：执行引擎（Codex / Claude / DimAgent / agy / ACP）、平台服务、斜杠命令、任务编排、多 Bot 协作、定时任务等，全都是独立插件。
- **配置声明式启用**：在根目录 `cordis.yml` 中声明启用的插件。不想用某项功能（如不需要定时任务或编排面板），直接在 `cordis.yml` 中删除对应行或设置 `disabled: true` 即可完全下线，核心代码无需改动一行。
- **服务解耦与类型化事件**：插件之间通过 `ctx.<service>`（如 `ctx.cli`、`ctx.cards`、`ctx.tasks`）与类型化事件（`bot/message`、`task/result` 等）协作，禁止跨插件强耦合。
